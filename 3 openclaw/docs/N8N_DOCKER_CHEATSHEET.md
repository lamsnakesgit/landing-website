# Шпаргалка по Docker и N8N (Learn & Troubleshooting)

В этом файле собраны ценные команды, которые помогли нам спасти сервер от переполнения и починить цикличные перезагрузки N8N.

## 1. Освобождение места на сервере (No space left on device)

Когда Docker задыхается от нехватки места, он не может скачать обновления или запустить базы данных.

**Очистка системных логов Docker (самая безопасная и эффективная):**
```bash
truncate -s 0 /var/lib/docker/containers/*/*-json.log
```
*Что это делает: Докер по умолчанию пишет все логи работы (console.log) в огромные JSON-файлы. Эта команда обнуляет их вес до 0 байт, не удаляя сами файлы, что абсолютно безопасно для работающих контейнеров.*

**Удаление зависших и неиспользуемых частей образов:**
```bash
docker image prune -f
```
*Что это делает: `prune` переводится как "подрезать". Добавка `-f` означает "без вопросов" (force). Удаляет загруженные из сети слои, которые не используются ни одним запущенным приложением.*

**Удаление конкретных контейнеров и их тяжелых образов (например, OpenClaw):**
```bash
docker rm -f openclaw openclaw_api openclaw_filebrowser
docker rmi $(docker images | grep openclaw | awk '{print $3}')
```
*Что это делает: Сначала `rm -f` жестко убивает запущенные контейнеры. Затем вторая строчка находит среди всех скачанных базовых образов (images) те, в названии которых есть слово "openclaw", забирает их ID (колонка 3) и передает команде `rmi` на удаление.*

## 2. Починка конфига N8N "на лету"

N8N часто ругается на права доступа (EACCES) к папкам, либо использует устаревшие переменные среды по-умолчанию.

Команды `sed` — это супер-инструмент сисадмина для поиска и замены текста в файлах без открытия редактора `nano`.

**Замена устаревшего пути на правильный:**
```bash
sed -i 's|N8N_BINARY_DATA_STORAGE_PATH=/data/binary|N8N_STORAGE_PATH=/home/node/.n8n/binary_data|g' /root/docker-compose.yml
```
*Расшифровка: `sed -i` значит "редактировать прямо в файле". Дальше идет блок `s|ЧТО ИЩЕМ|НА ЧТО МЕНЯЕМ|g`. Мы заменили папку, на которую у N8N не было прав, на родную папку пользователя внутри контейнера `node`, где он сам себе хозяин.*

**Удаление лишней строки:**
```bash
sed -i '/N8N_BINARY_DATA_TTL=24/d' /root/docker-compose.yml
```
*Расшифровка: Знак в конце `/d` означает удалить (delete) всю строчку целиком, если в ней найдено совпадение.*

## 3. Пересборка и запуск проектов (Docker Compose)

```bash
cd /root && docker compose down && docker compose up -d
```
*Расшифровка: Самая частая операция. Сначала переходим в ту папку, где лежит файл `docker-compose.yml`. Затем `down` аккуратно "гасит" все контейнеры, прописанные внутри файла и удаляет их старые пустые оболочки. И сразу же `up -d` собирает их заново из конфигурации, запуская в фоновом режиме (`-d` = deattached, чтобы консоль не зависла).*

## 4. Диагностика (Почему ничего не работает?)

**Посмотреть список запущенного:**
```bash
docker ps
```

**Отфильтровать список (найти только n8n):**
```bash
docker ps -a | grep n8n
```

**Прочитать последние 30 строчек "мыслей" контейнера (почему он упал):**
```bash
docker logs root-n8n-1 --tail 30
```
*Расшифровка: самая топовая команда для дебагга, чтобы не гадать, почему выдает "Bad Gateway 502" или "Cannot GET /", а посмотреть реальную внутреннюю ошибку.*
