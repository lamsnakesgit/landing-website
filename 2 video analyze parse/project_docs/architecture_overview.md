# Обзор архитектуры системы "Система контроля качества продаж"

## 1. Введение
Документ описывает высокоуровневую архитектуру системы, созданной для автоматизации контроля качества продаж, анализа диалогов и частичной замены функций руководителя отдела продаж (ROP). Основой системы является платформа автоматизации **n8n**, дополненная **Superpowers MCP** для расширенной функциональности, и **LLM (например, GPT-4/Gemini)** для интеллектуального анализа данных.

## 2. Основные компоненты системы

### 2.1. Источники данных (Data Sources)
-   **CRM (Bitrix24):** API для получения данных о сделках, контактах, менеджерах, истории взаимодействий.
-   **Телефонная система (например, Amo CRM/Voximplant):** API для получения записей звонков (аудио), данных о звонках (длительность, время, менеджер).
-   **Мессенджеры (WhatsApp, Telegram):** API или интеграции для получения переписок.
-   **Файловое хранилище (опционально):** Для хранения аудиозаписей, если они не доступны через API.

### 2.2. Сбор и обработка данных (Data Ingestion & Processing)
-   **n8n Workflows:**
    -   **Периодический сбор данных:** Регулярные воркфлоу для опроса API CRM и телефонии, получения новых/обновленных записей диалогов и сделок.
    -   **Обработка аудио:** Транскрибация аудиозаписей звонков в текст с использованием сервиса распознавания речи (например, OpenAI Whisper API, Google Speech-to-Text).
-   **База данных (PostgreSQL/MySQL):**
    -   **Хранение сырых данных:** Транскрибации, тексты переписок, метаданные (ID сделки, ID менеджера, время, источник).
    -   **Хранение аналитики:** Результаты анализа диалогов, оценки менеджеров, причины отказов, выявленные потребности.
    -   **Хранение конфигураций:** Скрипты, регламенты, критерии оценки лида, настройки воронки.

### 2.3. Модуль "Анализ диалогов" (Dialogue Analytics Engine)
-   **Ядро:** Python-скрипты или кастомные ноды n8n/Superpowers MCP.
-   **LLM (OpenAI API / Google Gemini API):**
    -   **Анализ соответствия скрипту:** Сравнение диалога с заданным скриптом, определение этапа продаж.
    -   **Оценка качества коммуникации:** Анализ эмпатии, структуры речи, профессионализма на основе промптов.
    -   **Выявление ошибок и рекомендаций:** Генерация фидбека для менеджера.
    -   **Анализ возражений и причин отказа:** Категоризация реплик клиента.
    -   **Выявление потребностей:** Поиск явных и неявных потребностей клиента.
-   **Логика оценки:**
    -   Расчет комплексного балла менеджера на основе набора параметров.
    -   Оценка качества лида (если заданы критерии).
    -   Определение "потенциала реанимации" сделки.

### 2.4. Модуль "Супервайзер" (Supervisor Agent)
-   **n8n Workflows:**
    -   **Мониторинг сделок:** Периодическая проверка сделок, находящихся на критических этапах воронки (например, "Закрыто нереализованно").
    -   **Логика оценки:** На основе данных из БД (результаты анализа диалога, статус сделки) принимает решение о действии.
-   **Действия:**
    -   **Создание задач в CRM:** Вызов API Bitrix24 для создания задачи для менеджера.
    -   **Возврат сделки в воронку:** Вызов API Bitrix24 для изменения статуса сделки.
    -   **Эскалация в Telegram:** Отправка сообщения в Telegram-чат для ROP.
-   **Superpowers MCP (опционально):** Для сложной логики оценки "потенциала реанимации" или кастомных вычислений.

### 2.5. Модуль "Ежемесячный аудит" (Monthly Audit Engine)
-   **n8n Workflows:**
    -   **Агрегация данных:** Сбор всех аналитических данных за месяц из БД.
    -   **Подготовка данных для LLM:** Формирование промпта на основе собранных данных.
-   **LLM (OpenAI API / Google Gemini API):**
    -   **Генерация отчета:** Создание one-page summary, анализа бизнес-модели, выявления тенденций, рекомендаций.
-   **Хранение отчетов:** Сохранение сгенерированных отчетов (PDF/HTML) в файловое хранилище или БД.

### 2.6. API Системы (System API)
-   **Технология:** Node.js/Express (если требуется внешний API) или нативные возможности n8n.
-   **Функционал:**
    -   Получение аналитики по менеджерам/сделкам для дашборда.
    -   Получение конфигураций (скрипты, регламенты).
    -   (Опционально) Webhook для приема данных от клиента.

### 2.7. Дашборды и отчетность (Dashboards & Reporting)
-   **Вариант 1 (n8n):** Использование встроенных дашбордов n8n для отображения данных.
-   **Вариант 2 (Веб-интерфейс):** Разработка простого веб-интерфейса на React/Vue.js, который потребляет данные из API системы.
-   **Telegram Bot:** Отправка ежедневных/еженедельных сводок по работе "Супервайзера".

### 2.8. Уведомления (Notifications)
-   **Telegram Bot API:** Отправка эскалаций, отчетов, уведомлений.

## 3. Поток данных (Data Flow)

1.  **Сбор (Ingestion):** n8n периодически опрашивает API CRM и телефонии, получает новые данные о сделках и диалогах.
2.  **Транскрибация (Transcription):** Аудиозаписи звонков отправляются на транскрибацию (Whisper API). Результат (текст) сохраняется в БД.
3.  **Хранение (Storage):** Все данные (тексты диалогов, метаданные, транскрибации) сохраняются в БД.
4.  **Анализ (Analysis):**
    -   n8n инициирует анализ новых диалогов через Python-скрипт/ноду, которая использует LLM.
    -   Результаты анализа (оценки, ошибки, рекомендации, причины отказов и т.д.) сохраняются в БД.
5.  **Мониторинг и Действия (Monitoring & Action):**
    -   Воркфлоу "Супервайзер" проверяет сделки в критических статусах.
    -   На основе данных из БД принимает решение и выполняет действия (создать задачу, вернуть сделку, эскалировать).
6.  **Агрегация и Отчеты (Aggregation & Reporting):**
    -   Ежемесячно n8n собирает данные из БД, отправляет в LLM для генерации отчета.
    -   Отчет сохраняется и отправляется пользователю.
7.  **Представление (Presentation):**
    -   Данные доступны через дашборды n8n или кастомный веб-интерфейс.
    -   Пользователи получают уведомления через Telegram.

## 4. Технологический стек в деталях

-   **n8n:** Центральный узел для оркестрации рабочих процессов, интеграций с внешними API, базовой логики.
-   **Superpowers MCP:** Позволяет расширять n8н кастомными нодами, написанными на JavaScript/TypeScript, для сложной логики, работы с данными, взаимодействия с другими сервисами.
-   **Python (опционально):** Для сложных скриптов анализа, если нативные возможности n8n/Superpowers MCP недостаточны. Можно запускать Python-скрипты из n8n через Execute Command node.
-   **LLM (OpenAI GPT-4 / Google Gemini):** "Мозг" системы для анализа текста, генерации отчетов, рекомендаций.
-   **PostgreSQL/MySQL:** Реляционная база данных для структурированного хранения данных.
-   **Node.js/Express:** (Опционально) для создания внешнего API, если нативные возможности n8n для экспорта данных не подходят.
-   **Telegram Bot API:** Для отправки уведомлений.
-   **Whisper API / Google Speech-to-Text:** Для транскрибации аудио.
