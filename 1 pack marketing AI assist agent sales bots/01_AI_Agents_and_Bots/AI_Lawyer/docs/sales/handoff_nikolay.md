# Handoff: Переписка с юристом (Николай) и выводы для продаж

## 1. Текущий статус клиента (Николай)
- **Ситуация:** Клиент ушел "думать до завтра".
- **Основная проблема:** Клиент не готов платить за "кастомную разработку" или "танцы с бубном". Ему не нужен парсер ради парсера.
- **Технический затык клиента:** Поиск только по ИИН/БИН ему недостаточен. Для его реальной работы нужен глубокий поиск по **категориям дел** (например, "Госзакупки", "Налоги", "Трудовые споры"), чтобы находить потенциальных клиентов или анализировать судебную практику по нишам.

## 2. Наши главные инсайты (Pivot проекта)
Этот негативный опыт общения — отличный сигнал для изменения бизнес-модели:
- **Отказ от заказной разработки:** Бегать за одним клиентом и делать всё руками под его хотелки — это не бизнес, а каторга.
- **Переход к SaaS-модели (IT-стартап):** Мы создаем **готового Telegram-бота / AI-ассистента** с подпиской. 
- **Главная ценность продукта:** Бот, который умеет сам искать судебные дела по категориям, анализировать их через ИИ (Claude/ChatGPT) и выдавать юристу готовую аналитику или лиды прямо в Telegram.

## 3. Стратегия продаж (Sales Strategy) на завтра
**Кому продаем:** 10+ новым юристам.
**Что продаем:** Не "разработку парсера", а **готовый продукт** (AI-ассистент для юриста).

### Оффер для новых лидов:
> "У нас есть готовый ИИ-ассистент, который в реальном времени мониторит Судебный Кабинет РК. Вы задаете ему категорию (например, Налоговые споры), и он не просто находит дела, но и с помощью ИИ делает краткую выжимку по исходам. Это работает прямо в Telegram. Хотите демо?"

### Следующие технические шаги для обеспечения продаж:
1. Доработать `sud_parser.py` для поиска по **категориям**, а не только по ИИН.
2. Упаковать этот поиск в Web MCP сервер (уже запущен на VPS).
3. Настроить связку, чтобы результаты парсинга автоматически скидывались в Telegram.
4. Выдавать доступ юристам по подписке (трекинг через TG ID).

## 4. Резюме для менеджера / ИИ-агента
**Статус Николая:** Поставлен на паузу (Cold/Follow-up). Не тратим на него активный ресурс. Если вернется — продаем ему уже готовую SaaS-подписку, а не кастомную доработку. Фокус смещен на масштабирование готового решения.
