# Telegram интеграция

> 📁 Базовые Bot API уведомления и примеры — в скилле `telegram`.
> 📁 Telegram Mini Apps — в скилле `telegram-mini-apps`.
> 📁 Валидация Telegram Mini App initData — в скилле `telegram-initdata-validation`.

## Когда что использовать
- Для отправки уведомлений, Bot API и простых bot-flow задач используй skill `telegram`.
- Для Telegram Mini Apps, TMA UI, Bot + WebApp flow и Telegram WebApp SDK используй skill `telegram-mini-apps`.
- Для безопасной аутентификации Mini App и проверки `initData` используй skill `telegram-initdata-validation`.

## Когда отправлять уведомления
- Отправляй уведомления для завершения задачи, ошибки, action-needed событий и регулярных отчётов.
- Для длинных задач отправляй прогресс только если он действительно полезен пользователю.
- Не отправляй уведомления на каждое мелкое действие и промежуточный шум.

## Правила отправки
- Уведомления должны отправляться фоном, без лишнего шума в основном ответе пользователю.
- Сообщения должны быть короткими, понятными и содержать только полезный контекст.
- Не отправляй секреты, токены, пароли, приватные ключи и чувствительные данные через Telegram.
- Если уведомление не несёт пользовательской ценности, его не нужно отправлять.

## Bot transport policy
- Для простых и dev-сценариев допустим long polling.
- Для production bot integrations с публичным endpoint предпочитай webhook.
- Выбор polling vs webhook держи в skill-слое, а не раздувай этим rule.

## Безопасность и границы
- Не храни bot token и другие секреты в коде или rules; используй переменные окружения или секреты платформы.
- Для hook-ов уведомлений (например `TaskComplete`) токен и chat id должны приходить из env (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`), а не храниться в самом hook-файле.
- Для Mini Apps никогда не доверяй `user_id` с клиента без проверки `initData`.
- Для сложных Telegram интеграций не пытайся решать всё одним rule — маршрутизируй в соответствующий skill.
