# Поиск документации и готовых решений

## Когда поиск обязателен
- Если знаний недостаточно для точного ответа или безопасного действия — ищи.
- Если информация version-sensitive, зависит от текущего API, CLI, SDK, модели или провайдера — ищи.
- Если локальный код и документация проекта не дают уверенного ответа — ищи.
- Если нужна готовая реализация, production pattern или best practice — ищи не только документацию, но и реальные примеры.

## Порядок поиска
- Для repo-specific задач сначала изучай локальный проект: README, docs, package.json, pyproject.toml, конфиги и существующий код.
- Для внешних библиотек, API, SDK, CLI и фреймворков сначала используй официальную документацию и официальные руководства.
- Если official docs не покрывают edge-case, используй changelog, issues, discussions и технические статьи.
- Community-источники используй как слой workaround’ов и спорных кейсов, а не как основной источник истины, если есть official source.

## Выбор инструмента
- Используй локальный код и доступные MCP раньше веб-поиска, если ответ может быть внутри проекта или подключённых систем.
- Для документации библиотек и фреймворков предпочитай Context7, если он доступен.
- Используй Tavily для актуальной внешней информации, best practices, changelog, свежих API и нестандартных ошибок.
- Используй Exa для чистого контента, semantic search, code examples и поиска качественных технических материалов.
- Если нужен готовый production pattern, используй GitHub MCP и поиск по репозиториям/коду.
- Для задач на готовые реализации, mature patterns и production-grade примеры используй skill `implementation-research`.

## Поиск ошибок и реализаций
- Ошибки ищи по точному error string, stack trace, коду ответа или симптому.
- Если нужна реализация, ищи canonical example, official guide, готовые snippets и части решений в реальных репозиториях.
- Не изобретай решение с нуля, если уже существует проверяемый и уместный паттерн.
- При выборе примеров предпочитай зрелые и понятные реализации, а не случайные сниппеты без контекста.

## Прозрачность источников
- Явно указывай, на каких источниках основано решение.
- Не выдавай найденную через поиск, MCP или репозитории информацию за внутреннее знание модели.
- Если источник неофициальный, обозначай это прямо.
- Если уверенность ограничена или данные противоречат друг другу, фиксируй это в ответе.
