# Ограничения PLAN MODE

## Что недоступно в PLAN MODE
- В PLAN MODE нельзя изменять файлы, запускать команды, выполнять MCP-инструменты и делать другие actions, требующие ACT MODE.
- PLAN MODE предназначен для исследования, чтения файлов, поиска, вопросов и проектирования решения.

## Что делать в PLAN MODE
- Используй `read_file`, `list_files`, `search_files` и другие read-only инструменты для сбора контекста.
- Используй поиск и документацию, если нужно добрать достоверность до реализации.
- Формируй конкретный план действий до начала изменений.
- Для проектных, архитектурных, multi-file и длинных задач SHOULD формировать план в 3 слоя:
  1. **Глобальный план** — цель, scope / non-scope, фазы, зависимости, definition of done и risks.
  2. **Средний план** — текущая фаза, 3–7 шагов внутри неё, проверка и следующий точный шаг.
  3. **Точечный чек-лист** — тот ближайший исполнимый slice, который потом перейдёт в `task_progress` после перехода в ACT MODE.
- В user-facing ответе PLAN MODE для project-задачи SHOULD показывать эти 3 слоя в кратком формате: `Что строим глобально` → `Средний план` → `Чек-лист`.
- Если глобальная цель проекта ещё не зафиксирована, PLAN MODE SHOULD сначала предложить её и согласовать с пользователем, а уже потом детализировать средний план и чек-лист.
- Для длинных задач SHOULD явно указывать, где будет жить каждый слой: `implementation_plan.md` / `docs/plan.md` для master plan, `cline_docs/project-state.md` для operational state, `task_progress` для текущего slice.
- MUST не смешивать уровни плана: не выдавать микро-чек-лист за master plan и не сводить весь проект к одному списку действий.
- Если требования неясны и это влияет на точность решения, задай уточняющий вопрос.

## Переход в ACT MODE
- Если для выполнения задачи нужны изменения файлов, команды, MCP или реальные действия, явно попроси пользователя переключиться в ACT MODE.
- Используй прямую формулировку: `Переключись на ACT MODE чтобы я мог выполнить изменения.`
- Не делай вид, что можешь завершить реализацию в PLAN MODE.

## Границы режима
- PLAN MODE — для исследования и планирования.
- ACT MODE — для реализации и проверки результата.
- Не путай план, предположение или архитектурную идею с реально выполненной работой.
