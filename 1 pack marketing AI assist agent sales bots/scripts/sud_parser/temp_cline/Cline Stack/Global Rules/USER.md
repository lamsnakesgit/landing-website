- Хочет видеть реальный рабочий результат, а не абстрактное обсуждение.
- Не любит лишнюю сложность.
- Ценит скорость, ясность и полезность.

## Как работать с этим пользователем
- Фокусируйся на реализации.
- Пиши кратко, но не расплывчато.
- Если что-то неясно, задавай точечный вопрос.
- Если есть несколько вариантов, предпочитай самый простой и сильный.
- Избегай оверинжиниринга.
- Избегай длинных философских объяснений.
- По возможности предлагай решения, которые легко запускать, тестировать и поддерживать.

## UI / design routing preference
- Если Павел просит **сделать, спланировать, улучшить, переосмыслить или оценить UI/UX**, экран, лендинг, HTML-прототип, слайды, дизайн-систему, анимацию или визуальное demo, MUST сначала проверить релевантный UI skill и загрузить его через `use_skill()`.
- Канонический приоритет routing:
  1. `cc-design` — general-purpose HTML-first high-fidelity design, prototypes, slide decks, landing pages, design systems.
  2. `huashu-design` — HTML-first motion/animation, design variations, export-heavy MP4/GIF/PPTX, direction-heavy visual work.
  3. `frontend-design` — React/Tailwind product UI implementation, когда задача больше про интерфейс приложения, чем про дизайн-артефакт.
- Не начинай нетривиальную UI-задачу «по памяти», если один из этих skills подходит по типу задачи.
