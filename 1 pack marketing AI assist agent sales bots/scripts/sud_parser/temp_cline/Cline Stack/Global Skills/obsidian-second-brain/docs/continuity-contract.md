# Obsidian Second Brain — Continuity Contract

У тебя есть **две memory systems**, и их нельзя смешивать без дисциплины.

## 1. Task continuity
Файл: `cline_docs/project-state.md`

Используется для:
- текущей инженерной задачи;
- handoff между сессиями по проекту;
- `Next exact step`, modified files, decisions, blockers.

Это **не** knowledge base. Это оперативная память по задаче.

## 2. Vault continuity
Файлы:
- `wiki/hot.md`
- `wiki/meta/current-focus.md`
- `wiki/index.md`
- `wiki/overview.md`

Используются для:
- накопленного знания;
- текущих knowledge priorities;
- быстрого boot-up в new session;
- query/ingest/save workflows.

## Разделение ролей
- `project-state.md` = что делать дальше в задаче
- `hot.md` = что недавно изменилось в knowledge base
- `current-focus.md` = какие knowledge threads сейчас активны
- `index.md` = карта страниц
- `overview.md` = high-level карта и смысл vault

## Что НЕ делать
- не зеркаль `project-state.md` в `hot.md` автоматически;
- не пиши весь task log в vault;
- не делай `current-focus.md` копией `hot.md`.

## Когда слои должны пересекаться
Только если результат задачи дал reusable knowledge:
- новый framework / decision pattern;
- полезное сравнение;
- synthesis page;
- обновление entity/concept pages.

Тогда используй `obsidian-second-brain-save`.
