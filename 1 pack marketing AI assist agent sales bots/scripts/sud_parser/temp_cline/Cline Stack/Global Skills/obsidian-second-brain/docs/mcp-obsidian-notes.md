# Notes on current mcp-obsidian setup

## Что подтверждено локально
Текущая установленная версия `mcp-obsidian` даёт два основных инструмента:
- `search_notes`
- `read_notes`

Это хороший слой для:
- поиска заметок по имени;
- чтения конкретных markdown-страниц;
- дешёвого discovery внутри vault.

## Чего он НЕ делает в этом setup
- не является полноценным write API;
- не заменяет обычные файловые операции для обновления vault;
- не должен быть единственным механизмом ведения второго мозга;
- не делает полнотекстовый search по body note.

## Практический паттерн использования
- поиск страниц по имени файла → через `search_notes`;
- чтение уже найденных страниц → через `read_notes`;
- обновление wiki → через filesystem tools;
- проверка качества структуры → через lint workflow.

## Ограничения
- hidden directories/files блокируются самим сервером;
- поэтому `.raw/` и другие скрытые папки не подходят, если ты хочешь их читать через MCP;
- для устойчивой работы лучше использовать обычные видимые папки (`raw/`, `wiki/`, `output/`).

## Важные практические детали
- Для `read_notes` используй относительные пути вида `raw/file.md` и `wiki/index.md`, а не пути с ведущим `/`.
- Если vault находится в symlink path вроде `/tmp` на macOS, для MCP-конфига и smoke-тестов лучше использовать `realpath`-вариант пути (`/private/tmp/...`).
- `search_notes` ищет по имени заметки/файла, а не по полному тексту документа.
- `search_notes` не нормализует пробелы и дефисы: запрос `Inbox Protocol` может не найти файл `inbox-protocol.md`, а запрос `inbox` — найдёт.
- Поэтому для content-level query сначала находи страницы через `index.md`/`hot.md`/короткий name search, а потом читай их напрямую.
