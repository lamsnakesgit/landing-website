# Parallel Work

## Sub-агенты (use_subagents)

Запуск до 5 параллельных sub-агентов. Каждый получает свой промпт и возвращает результат.

### Когда использовать
- Параллельное исследование нескольких файлов/директорий
- Сбор информации из разных источников (логи, конфиги, код)
- Best-of-N — несколько вариантов решения сложной задачи

### Когда НЕ использовать
- Простые задачи (overhead не стоит того)
- Задачи требующие последовательного выполнения
- Задачи где нужен контекст предыдущих шагов

### Примеры

**Параллельное исследование:**
```
prompt_1: "Найди все файлы с ошибками TypeScript в src/"
prompt_2: "Проверь зависимости в package.json"
prompt_3: "Проанализируй логи на сервере"
```

**Best-of-N:**
```
Запусти 3 sub-агентов для решения задачи оптимизации.
Каждый предлагает свой вариант. Верни все для сравнения.
```

### 🚨 Критические правила (проверено тестами + официальная документация)

- MUST передавать `prompt_1` как отдельный XML-параметр — NEVER оставлять пустым
- Sub-агенты **НЕ имеют доступа к MCP** (Brave Search, Tavily, GitHub, Railway и т.д.)
- Sub-агенты имеют только: `read_file`, `list_files`, `search_files`, `list_code_definition_names`, `execute_command`, `use_skill`
- `execute_command` в sub-агентах — только read-only: `ls`, `grep`, `git log`, `git diff`
- SHOULD запрашивать структурированный вывод (JSON) для удобной обработки результатов
- При ошибке файла — агент сообщает об ошибке и продолжает (не падает весь запуск)
- Каждый агент работает независимо — не видит результаты других агентов
- Sub-агенты должны возвращать **сжатые резюме** (1000-2000 токенов), не полные данные

### Что НЕ работает в sub-агентах
- ❌ `brave_web_search`, `tavily_search`, `tavily_extract`
- ❌ `github search_code`, `get_file_contents`
- ❌ `railway deploy`, `n8n-mcp` и другие MCP инструменты
- ✅ Только локальные файловые операции + read-only CLI + `use_skill`

### Структурированный вывод (рекомендуется)
```
prompt_1: "Прочитай файл X и верни JSON: {\"key\": \"...\", \"count\": 0}"
```

### Лимиты и ограничения
- Максимальный размер ответа: ~45,000 символов — при превышении таймаут
- Если нужно вернуть много данных — MUST сужать scope, дробить задачу или возвращать более короткое резюме вместо попытки вернуть всё сразу
- Известный баг: если у родителя включён `--thinking` (extended thinking) → sub-агенты возвращают HTTP 400. Решение: отключить `--thinking` у родителя.

### Отладка
```bash
# Просмотр логов sub-агентов
cline dev log
```

## Git worktrees для изоляции

### Когда использовать
- Нужно работать с несколькими задачами параллельно
- Задачи могут затрагивать одни и те же файлы, но только при явной координации и изоляции
- Нужно протестировать разные подходы

```bash
# Создать worktree
git worktree add ../myproject-feature -b feature

# Работать в изолированной копии
cd ../myproject-feature

# Удалить после завершения
git worktree remove ../myproject-feature
```

### Правила
- MUST давать worktree понятное имя (feature, bugfix, refactor)
- MUST удалять worktree после завершения задачи
- SHOULD проверять что нет незакоммиченных изменений перед удалением
- SHOULD удостоверяться, что нужные изменения сохранены или сознательно отброшены до cleanup

## Контракты между sub-агентами

🚨 MUST определять контракты **до** запуска sub-агентов.

Контракт — соглашение о том:
- Что делает каждый sub-агент
- Какие файлы/данные использует
- Какой результат возвращает
- Какие зависимости от других агентов

### Порядок запуска
Сначала upstream (те от которых зависят другие), потом downstream.

**Пример:**
```
Sub-агент 1: определяет схему БД → возвращает SQL + описание полей
Sub-агент 2: строит бэкенд на основе схемы → возвращает список эндпоинтов
Sub-агент 3: строит фронтенд на основе API → возвращает список компонентов
```

### Правила
- MUST определять контракты до запуска
- MUST запускать upstream первыми
- SHOULD проверять результат каждого sub-агента
- NEVER принимать «я закончил» без проверки
- SHOULD разделять зоны ответственности чтобы избежать файловых конфликтов

## Сравнение подходов

| Подход | Когда использовать |
|---|---|
| **Sub-агенты** | Параллельное исследование, сбор информации |
| **Git worktrees** | Изолированная работа с кодом |
| **Headless (VPS)** | Регулярные задачи по расписанию |

## Главный принцип

80% работы с командами агентов = планирование и ревью. 20% = реализация.
Чёткая задача → хороший результат. Размытая → конфликты и ошибки.
