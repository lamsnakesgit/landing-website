# Obsidian Second Brain Ingest

Превращай новые источники из `raw/` в структурированные wiki-страницы.

## Когда использовать
- пользователь добавил файл в `raw/`;
- пользователь просит ingest/import/process a source;
- нужно обновить wiki новыми знаниями.

## Когда НЕ использовать
- вопрос уже относится к существующему знанию и не требует ingest;
- нужен просто ответ по уже существующим страницам — тогда используй query skill.

## Workflow
1. Определи, какие источники нужно обработать.
2. Для новых материалов предпочитай `raw/inbox/`; legacy источники в корне `raw/` допустимы, но новые лучше туда не складывать.
3. Прочитай источник полностью.
4. Если пользователь не сказал «ингести сразу», сначала дай 3–5 ключевых takeaway.
5. Создай или обнови source summary в `wiki/sources/` по шаблону.
6. Создай или обнови страницы в `wiki/entities/` и `wiki/concepts/` по шаблонам.
7. Если появляется ценный synthesis-артефакт — сохрани его в `wiki/comparisons/` или `wiki/questions/`.
8. Добавь `[[wikilinks]]` между связанными страницами.
9. Для крупных ingest-операций сначала можно собрать candidate result в `output/review/`, потом переносить в live wiki.
10. Обнови `wiki/index.md`, `wiki/log.md`, `wiki/hot.md` и при необходимости `wiki/meta/current-focus.md`.
11. После ingest переведи источник в `raw/processed/` или явно зафиксируй его как обработанный в логе.
12. Зафиксируй противоречия и knowledge gaps явно.

## Практические правила
- сначала ищи существующие страницы, потом создавай новые;
- один источник может затронуть 5–15 страниц — это нормально;
- source page должна быть фактической, а synthesis — жить отдельно;
- `raw/` — источник истины, не переписывай его без причины;
- если ingest изменил active priorities пользователя, обновляй `current-focus.md` коротко и фактологично;
- если нужен более интересный graph view, сначала усиливай entity pages и links, а не усложняй инфраструктуру.

## Smoke tests
- «Я закинул статью в raw/, разложи её по vault» → появляется source summary + обновляются entity/concept pages.
- «Переингести эту заметку и обнови связанные страницы» → skill сравнивает текущее состояние и обновляет только нужное.
- «У меня много новых материалов, но не хочу ломать live wiki» → skill использует `output/review/` и approve-паттерн.

## Red flags
- дублировать entity/concept pages вместо update existing;
- отвечать по памяти, не читая raw/source summary;
- забыть обновить hot/index/log после значимого ingest;
- складывать все новые источники в корень `raw/`, если уже есть `raw/inbox/`.
