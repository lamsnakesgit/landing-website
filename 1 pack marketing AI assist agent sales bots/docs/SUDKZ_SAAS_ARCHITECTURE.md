# Архитектура SaaS-платформы: AI-Поиск по Судебному кабинету (Sud.kz)

## 📌 1. Бизнес-цель
Предоставить юристам B2B SaaS-решение по подписке для интеллектуального поиска и анализа судебных актов. Юрист общается с ИИ-ассистентом на естественном языке, а ИИ автоматически ищет, скачивает и анализирует дела из закрытой базы "Судебный кабинет РК" (office.sud.kz), выдавая готовую выжимку в Excel.

## 🏗 2. Выбор стека (Архитектура "Агент-Прокладка")

Вместо разработки собственного сложного фронтенда с нуля, используется готовая связка:
1. **Витрина (Frontend):** `Open WebUI` (развернут на VPS). Бесплатный интерфейс в стиле ChatGPT со встроенной авторизацией пользователей, админкой и лимитами. (Альтернатива: Telegram бот + n8n).
2. **Мозг (LLM):** `Gemini 1.5 Pro` (или аналогичная модель с большим контекстным окном).
3. **Движок (Tool/MCP):** Python-скрипт `sud_parser_vps.py` (с авторизацией ЭЦП НУЦ РК / Калкан). Обернут в функцию (Tool), которую может вызывать ИИ.

## ⚙️ 3. Распределение ролей (ИИ vs Код)

> **Критическое правило:** ИИ **не должен** читать 10 000 дел. Скрипт **не должен** качать 10 000 дел.

### Правильный Core Workflow:
1. **Понимание (ИИ):** Юрист пишет сложный запрос ("Найди дела по кадастру, где иск удовлетворили"). ИИ через механизм **Function Calling** извлекает параметры: `main_query="кадастр"`, `resolution="удовлетворить"`.
2. **Разведка (Код):** Скрипт получает параметры от ИИ, идет в СудКаб и нажимает "Поиск".
3. **Фильтр объема (Код):** Если СудКаб выдает результат > 50-100 дел, скрипт **отменяет скачивание** и возвращает ИИ сообщение: *"Слишком много результатов (10 000). Попроси пользователя сузить поиск"*. 
4. **Уточнение (ИИ):** ИИ пишет юристу: *"Найдено слишком много дел. Уточните регион или инстанцию"*.
5. **Выгрузка (Код):** Когда найдено приемлемое число дел (например, 30), скрипт скачивает их PDF, переводит в текст и отдает обратно ИИ.
6. **Анализ (ИИ):** ИИ читает текст 30 дел, выбирает самые релевантные и формирует итоговый Excel/Markdown отчет для юриста.

## 💰 4. Экономика (Монетизация)
- Владелец SaaS продает подписку за фиксированную сумму (например, $100/мес).
- Владелец SaaS оплачивает только API-токены (Gemini/OpenAI) по факту использования.
- Ограничение от "скликивания" (сжигания токенов) настраивается в админ-панели Open WebUI (лимит сообщений в день/месяц на пользователя).

## 🚀 5. Технический Бэклог (Ближайшие шаги для агентов)

**ЗАДАЧА №1 (В приоритете):**
Модифицировать "экскаватор" — текущий код `sud_parser_vps.py`. 
В данный момент парсер жестко зашит на выгрузку по `category_id` и `edit-period` (Год). 
Необходимо:
- Исследовать HTML-форму поиска на office.sud.kz.
- Найти имена полей (name/id) для текстового ввода ("Основной поиск", "Резолютивная часть", "Истец", "Ответчик").
- Добавить эти поля в AJAX payload `data_search` внутри Python-скрипта, чтобы скрипт мог принимать динамические текстовые переменные.
- Обернуть скрипт в интерфейс Tool/Function для интеграции с Open WebUI/n8n.
