# Руководство по авторизации и парсингу Судебного Кабинета (office.sud.kz)

Данное руководство описывает весь процесс, подводные камни, ошибки и их решения при автоматизации взаимодействия с порталом office.sud.kz, который использует ЭЦП (НУЦ РК) для входа и JSF/RichFaces для рендеринга и навигации.

## 1. Архитектура портала и технологии

Сайт `office.sud.kz` построен на старом Java-стеке:
- **JSF (JavaServer Faces)** — управляет состоянием страниц на сервере.
- **RichFaces** — библиотека компонентов поверх JSF, активно использующая AJAX.

**Важно:** Сайт не использует классический REST API. Все действия (кнопки, ссылки, поиск) работают через POST-запросы, в которых передается текущее состояние страницы (`javax.faces.ViewState`). Без актуального `ViewState` сервер отклонит запрос.

## 2. Авторизация по ЭЦП (KalkanCrypt)

Авторизация на портале состоит из нескольких шагов:

### Шаг 2.1: Получение исходного XML для подписи
Нужно сделать GET-запрос на главную страницу (или страницу входа) и найти внутри HTML скрытый или закомментированный XML, который требуется подписать.
Обычно он выглядит так:
```xml
<loginInfoForSign><nonce>282-3580-4598-a664-9602f3aee744</loginInfoForSign>
```

### Шаг 2.2: Подписание XML
Подписание происходит с использованием библиотеки KalkanCrypt (C/C++). 
Попытки использовать чистый Python (pyOpenSSL, signxml) проваливаются, так как портал требует ГОСТ-подпись в формате CMS/XMLDSIG по стандартам НУЦ РК.
**Решение:** Был создан Docker-контейнер (AlmaLinux 8), внутри которого установлена официальная библиотека `libkalkancrypto.so` и написана обертка на C (`kalkan_sign.c`), которая вызывается из Python через `subprocess`.

**Ошибки и нюансы KalkanCrypt:**
- KalkanCrypt требует наличия корневых сертификатов НУЦ РК в хранилище (или загрузки их через `KC_LoadKeyStore`).
- Требуется пароль от файла `.p12`.
- Возвращаемый подписанный XML вставляется обратно в форму авторизации.

### Шаг 2.3: Отправка подписанного XML (AJAX-авторизация)
На сайте кнопка "Войти" — это AJAX-компонент RichFaces. Отправка POST-запроса должна имитировать этот AJAX-вызов.
```python
login_data = {
    "j_idt73:j_idt93": "j_idt73:j_idt93",           # ID формы
    "javax.faces.ViewState": view_state,            # Состояние
    "javax.faces.partial.ajax": "true",             # Указатель для RichFaces
    "javax.faces.source": "j_idt73:j_idt93:j_idt94:j_idt118", # ID кнопки
    "javax.faces.partial.execute": "@all",
    "javax.faces.partial.render": "@all",
    "j_idt73:j_idt93:j_idt94:j_idt118": "j_idt73:j_idt93:j_idt94:j_idt118", 
    "j_idt73:j_idt93:j_idt94:signedXml": signed_xml # Подписанный XML
}
```
**Результат:** Сервер возвращает HTTP 200 и куку сессии `JSESSIONID`.

## 3. Парсинг Банка судебных актов (Поиск)

Переход к поиску (например, по категории "Трудовые споры") также не тривиален.

### Проблема: Ошибки 500 или пустые ответы
Если отправить POST-запрос с заполненными полями поиска (категория, период), сервер может выдать `HTTP 500` или не вернуть результаты.
**Причины:**
1. Обязательные чекбоксы. JSF форма требует передачи значений обязательных элементов. В частности, чекбокс инстанции `edit-participantTypeCheckbox` (значение `FIRSTINSTANCE`).
2. Неправильный ID кнопки. AJAX-запрос должен триггерить кнопку поиска (напр. `j_idt138`).

### Проблема: Перенаправление внутри Partial-Response
Когда поиск успешен, JSF **не возвращает HTML** с результатами. Он возвращает XML-документ с инструкцией редиректа:
```xml
<partial-response id="j_id1">
  <redirect url="/form/courtActs/lawsuitList.xhtml"></redirect>
</partial-response>
```
**Решение:** Парсер должен вручную перехватить этот редирект и сделать отдельный `GET`-запрос по указанному URL (`/form/courtActs/lawsuitList.xhtml`), чтобы получить таблицу с найденными делами.

## 4. Переход к деталям судебного дела

В таблице результатов каждая строка кликабельна: `onclick="viewSelectedLawsuit('0')"`.
Это означает, что нужно сделать AJAX POST запрос, передав параметр `param1` со значением (индексом дела).

```python
data_case = {
    # ... стандартные AJAX поля ...
    "param1": "0" # Индекс дела из onclick
}
resp_case = session.post(f"{BASE_URL}/form/courtActs/lawsuitList.xhtml", data=data_case)
```
**Результат:** Сервер снова возвращает XML-редирект на `/form/courtActs/documentList.xhtml`.
После перехода по этому URL `GET`-запросом, загружается страница со списком прикрепленных документов (решения, постановления в PDF).

## 5. Документы и Капча (Решено через ddddocr)

При попытке скачать сам документ (например, "Шешім.pdf"), на странице используется ссылка `onclick="downloadSelectedDoc(0, 0);"`.
Этот вызов вызывает AJAX-запрос, который **открывает модальное окно с капчей**:
`<div id="captchaModalDialog" class="modal" ...>`
Внутри окна загружается картинка `/img/captcha.jpg` и требуется ввести "Суреттегі цифрларды енгізіңіз".

**Решение (ddddocr):**
Вместо использования платных API (RuCaptcha/2Captcha), в контейнер установлена библиотека **`ddddocr`** (легковесная нейросеть для распознавания простых капч локально).
Парсер выполняет следующие шаги:
1. Вызывает `downloadSelectedDoc()`.
2. Скачивает `/img/captcha.jpg`.
3. Распознает капчу через `ddddocr.DdddOcr()`.
4. Отправляет POST-запрос с формой `captchaForm` и решенным текстом.
5. Сервер возвращает параметры `n` (ID файла) и `u` (тикет) в ответе `hideDownloadLinkPanel`.
6. Выполняется скачивание самого PDF-файла через `/ticket/fileDownload`.

## 7. Среда выполнения (VPS)

Во избежание проблем с совместимостью OpenSSL на Mac (конфликт старого LibreSSL и новых urllib3), а также для работы 24/7, код **работает на удаленном VPS сервере** (AlmaLinux 8, IP: `151.241.100.226`).

- **Запуск:** Скрипт `deploy.py` собирает Docker-образ локально на VPS по SSH, загружает туда KalkanCrypt, `ddddocr` и Python-парсер, после чего запускает контейнер. Результаты и PDF файлы скачиваются обратно на Mac в папку `output/pdfs/`.
- **Ресурсы:** VPS имеет 4GB RAM (~100MB free, 1.5GB swap) и 96GB диск (~40GB свободно). RAM ограничена, так как крутятся другие Docker-контейнеры (Postgres, Redis, Evolution API, WordPress). Поэтому парсер запускается как временный `--rm` контейнер и после завершения освобождает ресурсы.

## 6. Резюме для агентов

1. **Не ломайте Docker-контейнер и библиотеку KalkanCrypt.** C-обертка (`kalkan_sign.c`) — самый стабильный способ работы с ЭЦП НУЦ РК.
2. **Всегда парсите `ViewState`.** Каждая загрузка страницы генерирует новый `ViewState`. Без него POST-запросы не работают.
3. **Читайте XML-ответы JSF.** Если пришел `partial-response` с `redirect`, всегда делайте следующий GET-запрос.
4. **JSF ID меняются.** Идентификаторы вроде `j_idt73` могут меняться при обновлениях портала. Если парсер ломается, сначала проверьте актуальные ID кнопок и форм через браузер (DevTools -> Network).
