# Траблшутинг запуска ComfyUI в Google Colab

В этом документе зафиксированы технические проблемы, возникшие при запуске ComfyUI в облачной среде Google Colab, причины их возникновения, предложенный код, результаты тестов и финальные решения.

## 1. Проблема: Конфликт версий PyTorch при установке через Pip

### Описание и симптомы
При установке зависимостей с помощью pip процесс установки зависал на этапе разрешения зависимостей (dependency resolution) на библиотеке `MarkupSafe` или других пакетах, длящихся более 20 минут.

### Изначально предложенный код
```bash
!pip install torch torchvision torchaudio --extra-index-url https://download.pytorch.org/whl/cu121
!pip install -r requirements.txt
```

### Причина ошибки
В Google Colab среда выполнения GPU (T4/A100) по умолчанию уже содержит предустановленные и оптимизированные версии `torch`, `torchvision` и `torchaudio` с поддержкой CUDA. Попытка принудительно переустановить их или обновить через pip приводила к конфликтам версий и бесконечному циклу разрешения зависимостей pip.

### Что пробовали и к чему привело
1. Пробовали ждать разрешения зависимостей — привело к зависанию сессии и таймауту Colab.
2. Пробовали установить с флагом `--no-deps` — привело к поломке импортов в самом PyTorch.

### Как решили (Финальный код)
Из скрипта запуска полностью удалили принудительную установку PyTorch. Оставили только установку легковесных зависимостей самого ComfyUI:
```bash
!pip install -r requirements.txt
```
* **Результат:** Время прохождения шага сократилось с зависания до 5–10 секунд. Среда использует встроенный оптимизированный PyTorch.

## 2. Проблема: Ошибка запуска `unrecognized arguments: --share`

### Описание и симптомы
При попытке запустить ComfyUI с публичным доступом через стандартный флаг share выполнение аварийно завершалось с ошибкой в консоли:
```text
main.py: error: unrecognized arguments: --share
```

### Изначально предложенный код
```bash
!python main.py --share
```

### Причина ошибки
В современных версиях ComfyUI аргумент `--share` больше не поддерживается скриптом запуска `main.py`.

### Что пробовали и к чему привело
1. Пробовали запустить через `colab_bootstrap.py` — несовместимо с последними обновлениями нод.
2. Рассматривали запуск через `Ngrok` — требует от пользователя регистрации и ввода токена авторизации, что усложняет запуск.
3. Решили использовать **Cloudflare Tunnel (cloudflared)** — он полностью бесплатен, не требует регистрации и токенов для базовых туннелей.

### Как решили (Финальный код)
ComfyUI запускается локально в фоновом режиме на стандартном порту `8188`. Параллельно скачивается официальный бинарник `cloudflared` и запускается туннель, проксирующий порт `8188` во внешнюю сеть:
```python
# Запуск ComfyUI в фоне
import subprocess
import time
subprocess.Popen(["python", "main.py", "--port", "8188", "--dont-print-server"])
time.sleep(5)

# Скачивание cloudflared
!wget -q https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -O cloudflared
!chmod +x cloudflared

# Запуск туннеля
subprocess.Popen(["./cloudflared", "tunnel", "--url", "http://127.0.0.1:8188"])
```
* **Результат:** ComfyUI работает локально, туннель успешно перенаправляет трафик, но возникла следующая проблема с выводом ссылки.

## 3. Проблема: Ошибка `IndexError: list index out of range` при парсинге логов Cloudflare

### Описание и симптомы
Скрипт аварийно завершался на этапе парсинга ссылки туннеля из стандартного вывода со следующей ошибкой:
```text
IndexError: list index out of range
```
Ошибка возникала на строке: `url = line.split("https://")[1].strip()`

### Изначально предложенный код парсинга логов
```python
tunnel = subprocess.Popen(["./cloudflared", "tunnel", "--url", "http://127.0.0.1:8188"], stdout=subprocess.PIPE, stderr=subprocess.STDOUT, text=True)
for line in tunnel.stdout:
    if "trycloudflare.com" in line:
        url = line.split("https://")[1].strip()
        print("\n\n🔥 ВАША ССЫЛКА: https://" + url + "\n\n")
        break
```

### Причина ошибки
Инструмент `cloudflared` при запуске выводит в консоль множество технических логов. Один из логов содержал домен `trycloudflare.com` (например, информацию о подключении к серверам Cloudflare), но не содержал протокола `https://`. Скрипт среагировал на ключевое слово домена, попытался разбить строку по `https://`, получил список из одного элемента и упал при попытке обратиться к индексу `[1]`.

### Что пробовали и к чему привело
1. Пробовали искать регулярным выражением `re.search` — код стал избыточно сложным.
2. Пробовали обрабатывать через `try-except` — скрипт пропускал нужную строку и уходил в бесконечный цикл ожидания.

### Как решили (Финальный код)
Добавили жесткое условие: строка лога должна одновременно содержать и домен `trycloudflare.com`, и протокол `https://`. Также добавили очистку от лишних символов (пробелы, символы пайпа `|`):
```python
tunnel = subprocess.Popen(["./cloudflared", "tunnel", "--url", "http://127.0.0.1:8188"], stdout=subprocess.PIPE, stderr=subprocess.STDOUT, text=True)

for line in tunnel.stdout:
    if "trycloudflare.com" in line and "https://" in line:
        parts = line.split("https://")
        if len(parts) > 1:
            url = parts[1].strip().split(" ")[0].strip("|").strip()
            print("\n\n🔥 ВАША ССЫЛКА НА COMFYUI: https://" + url + "\n\n")
            break
```
* **Результат:** Парсинг работает стабильно, ссылка выводится в консоль без ошибок, сессия Colab продолжает жить.

## 4. Проблема: Ссылка `trycloudflare.com` выдает Connection Refused / 502 Bad Gateway

### Описание и симптомы
Ссылка туннеля генерируется и выводится в консоль, но при переходе по ней веб-страница выдает ошибку `502 Bad Gateway` или бесконечно грузится, выдавая ошибку подключения.

### Изначально предложенный код запуска
```python
# ComfyUI запускался в фоне
subprocess.Popen(["python", "main.py", "--port", "8188", "--dont-print-server"])
time.sleep(5)

# Туннель запускался вслепую
subprocess.Popen(["./cloudflared", "tunnel", "--url", "http://127.0.0.1:8188"])
```

### Причина ошибки
1. **Скрытые ошибки:** ComfyUI запускался в фоновом режиме через `subprocess.Popen`. Если при инициализации (импорте библиотек, загрузке моделей или CUDA) происходила ошибка, процесс Python аварийно завершался. Поскольку вывод сервера был скрыт от пользователя, тот видел только успешную генерацию ссылки от работающего процесса `cloudflared`.
2. **Преждевременный старт туннеля:** Туннель запускался через жестко заданную паузу `time.sleep(5)`. На GPU T4 в Colab первый старт ComfyUI может занимать до 1.5–2 минут, в течение которых порт `8188` закрыт.

### Что пробовали и к чему привело
1. Пробовали увеличить `time.sleep(5)` до `time.sleep(30)` — это не решило проблему, если сервер падал на этапе загрузки модели.
2. Пробовали запустить напрямую `!python main.py --share` — не работает (флаг не поддерживается).

### Как решили (Финальный код)
Разработано архитектурное решение на базе официального паттерна `ComfyUI-Manager`:
1. Скачивание и установка `cloudflared` производится через пакетный менеджер системы (`dpkg -i`) для глобальной доступности утилиты.
2. Запуск туннелирования перенесен в фоновый поток Python (`threading.Thread`). Поток циклически пингует локальный сокет на порту `8188` с интервалом `0.5` секунд. Как только сокет возвращает `0` (сервер поднялся и слушает порт), запускается туннель Cloudflared, перехватываются его логи из `stderr` и выводится ссылка.
3. Сам ComfyUI запускается на переднем плане (`!python main.py`), благодаря чему пользователь видит реальный интерактивный вывод сервера в консоли Colab и может диагностировать любые сбои.

```python
# Установка через deb
!wget -q https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
!dpkg -i cloudflared-linux-amd64.deb

import subprocess
import threading
import time
import socket

def tunnel_thread(port):
    print("\n[Туннель] Ожидаем запуск веб-сервера ComfyUI на порту {}...\n".format(port))
    while True:
        time.sleep(0.5)
        sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        result = sock.connect_ex(('127.0.0.1', port))
        if result == 0:
            break
        sock.close()
    
    print("\n[Туннель] ComfyUI успешно запущен! Подключаем туннель Cloudflare...\n")
    p = subprocess.Popen(["cloudflared", "tunnel", "--url", "http://127.0.0.1:{}".format(port)], 
                         stdout=subprocess.PIPE, stderr=subprocess.PIPE)
    
    for line in p.stderr:
        l = line.decode()
        if "trycloudflare.com" in l and "https://" in l:
            idx = l.find("https://")
            url = l[idx:].strip().split(" ")[0].strip("|").strip()
            print("\n\n🔥 ВАША ССЫЛКА НА COMFYUI: " + url + "\n\n")
            break

# Запуск фонового потока проверки сокета и туннеля
threading.Thread(target=tunnel_thread, daemon=True, args=(8188,)).start()

# Запуск сервера на переднем плане
!python main.py --dont-print-server
```
* **Результат:** Ссылка генерируется только после полной готовности веб-сервера, любые ошибки запуска выводятся прямо на экран.

## 5. Проблема: Бесконечное накопление вложенности папок при перезапуске ячейки

### Описание и симптомы
При многократном нажатии кнопки «Стоп» и повторном запуске ячейки, ComfyUI перестает открываться. В логах пользователя отображается странный путь:
`/content/ComfyUI/ComfyUI/ComfyUI/ComfyUI/ComfyUI`
Исполнение `python main.py` завершается с ошибкой `can't open file 'main.py': [Errno 2] No such file or directory`, но поскольку вывод был скрыт или шел в фоновом режиме, пользователь получал нерабочую ссылку.

### Изначально предложенный код
```python
if not os.path.exists('ComfyUI'):
    !git clone https://github.com/comfyanonymous/ComfyUI.git
%cd ComfyUI
```

### Причина ошибки
В Google Colab команда `%cd ComfyUI` меняет текущую рабочую директорию сессии. При повторном запуске ячейки без сброса пути сессия находится в `/content/ComfyUI` и пытается зайти еще глубже: `%cd ComfyUI` переводит её в `/content/ComfyUI/ComfyUI`, затем в `/content/ComfyUI/ComfyUI/ComfyUI` и так далее. Файл `main.py` находится только в первой папке `/content/ComfyUI`, поэтому во вложенных папках запуск падал.

### Что пробовали и к чему привело
1. Пробовали использовать относительные пути `python ComfyUI/main.py` — приводит к ошибке, если мы уже находимся внутри `ComfyUI`.

### Как решили (Финальный код)
В самое начало ячейки добавлена явная директива принудительного возврата в корень Google Colab (`/content`):
```python
# 0. Сбрасываем рабочую директорию в корень Colab для избежания вложенности
%cd /content
```
* **Результат:** Путь гарантированно сбрасывается перед каждым запуском, вложенность папок больше не накапливается, запуск всегда происходит из правильной директории `/content/ComfyUI`.

## 6. Проблема: Ссылка trycloudflare выдает HTTP Error 403 / бесконечную загрузку пустого экрана

### Описание и симптомы
При запуске туннеля генерировалась публичная ссылка, но при попытке открыть ее в браузере пользователь получал ошибку `HTTP ERROR 403` или серый пустой экран с логотипом Comfy посередине.

### Изначально предложенный код запуска
```python
# ComfyUI запускался с биндингом на 127.0.0.1
!python main.py --listen 127.0.0.1 --port 8188 --dont-print-server
```

### Причина ошибки
1. **Блокировка порта 8188:** Прошлый фоновый процесс Python не освободил порт `8188`, из-за чего ComfyUI упал на старте, а Cloudflared проксировал пустой/занятый порт.
2. **Блокировка CORS / Host Origin:** Cloudflare Tunnel проксирует запросы с внешнего домена (`*.trycloudflare.com`) на локальный адрес. ComfyUI блокирует такие запросы на уровне CORS, если не передан специальный флаг.

### Что пробовали и к чему привело
1. Пробовали запустить без флагов — ComfyUI не принимал запросы извне.
2. Настроили принудительное убийство процессов на порту 8188 через `fuser -k 8188/tcp` перед стартом.
3. Добавили параметр `--enable-cors-header` для пропуска внешних запросов от Cloudflared.

### Как решили (Финальный код)
Скрипт был обновлен для автоматического высвобождения порта перед запуском и активации CORS-заголовков:
```python
# Высвобождение порта
!fuser -k 8188/tcp || true

# Запуск ComfyUI с поддержкой CORS для туннеля
!python main.py --listen 127.0.0.1 --port 8188 --enable-cors-header --dont-print-server
```
* **Результат:** Порт гарантированно чист перед каждым запуском, интерфейс ComfyUI успешно загружается через туннель без блокировок CORS (на экране отображается логотип загрузки ComfyUI).

## 7. Проблема: Постоянные разрывы соединения и ошибка "Error 1033 / Reconnecting" на trycloudflare

### Описание и симптомы
После успешного входа в веб-интерфейс соединение обрывалось через несколько минут простоя, выдавая ошибку переподключения (`Reconnecting`) или ошибку `Error 1033: Cloudflare Tunnel error`.

### Изначально предложенный код запуска туннеля
```python
p = subprocess.Popen(["cloudflared", "tunnel", "--url", "http://127.0.0.1:{}".format(port)], 
                     stdout=subprocess.PIPE, stderr=subprocess.PIPE)
```

### Причина ошибки
По умолчанию `cloudflared` настраивает туннель через сетевой протокол QUIC (работает поверх UDP). В бесплатных/облачных окружениях вроде Google Colab, или при использовании определенных провайдеров, UDP-соединения быстро сбрасываются из-за неактивности или блокируются фильтрами безопасности, что моментально ломает WebSocket-соединения ComfyUI.

### Что пробовали и к чему привело
1. Пробовали обновлять страницу — спасало лишь временно, затем туннель полностью падал.
2. Перевели передачу данных с QUIC на **HTTP/2** (который работает по надежному TCP и стабильно держит WebSocket-соединение с ComfyUI без тайм-аутов).

### Как решили (Финальный код)
В параметры вызова бинарника `cloudflared` добавлен флаг принудительного использования протокола HTTP/2:
```python
p = subprocess.Popen(["cloudflared", "tunnel", "--protocol", "http2", "--url", "http://127.0.0.1:{}".format(port)], 
                     stdout=subprocess.PIPE, stderr=subprocess.PIPE)
```
* **Результат:** Трафик идет по протоколу HTTP/2 (TCP). Веб-сокеты не разрываются, интерфейс стабилен при простое и плашка «Reconnecting / Error 1033» больше не возникает.

## 8. Проблема: Блокировка IP-диапазона Google Colab со стороны Cloudflare (Error 1033)

### Описание и симптомы
Даже при использовании HTTP/2 соединения, при перезапуске ячеек Cloudflare выдавал ошибку `Error 1033: Cloudflare Tunnel error` на стороне своего Edge-сервера, не позволяя подключиться к туннелю.

### Изначально предложенный код
```python
# Использовался Cloudflare Tunnel
p = subprocess.Popen(["cloudflared", "tunnel", "--protocol", "http2", ...])
```

### Причина ошибки
IP-адреса дата-центров Google Colab часто используются для парсинга и спама, из-за чего Cloudflare превентивно блокирует сессии бесплатных туннелей `trycloudflare.com`, генерируя Error 1033.

### Что пробовали и к чему привело
Поскольку Cloudflare забанил IP-диапазон сессии Colab, мы заменили его на альтернативный инструмент проброса портов — **Localtunnel** (утилита на npm, которая не блокирует IP Google Colab и стабильно держит WebSocket-соединение с прохождением авторизации по внешнему IP-адресу машины Colab).

### Как решили (Финальный код)
Скрипт был переписан на использование пакета `localtunnel`:
1. Установка глобально через npm: `!npm install -g localtunnel`
2. Вывод внешнего IP-адреса машины Colab (используется как пароль).
3. Запуск туннеля: `p = subprocess.Popen(["lt", "--port", "8188"])`
```python
# Установка и запуск туннеля через lt
!npm install -g localtunnel
!curl ipv4.icanhazip.com  # Пароль для входа
p = subprocess.Popen(["lt", "--port", "8188"])
```
* **Результат:** Ссылка генерируется через домен `*.loca.lt`, которая не блокируется Cloudflare, а веб-сокеты ComfyUI стабильно работают без обрывов.

## 9. Проблема: Ошибка "Отсутствующие пакеты узлов" (Неизвестный пакет) в Web UI и требование установить Node Manager

### Описание и симптомы
При импорте JSON воркфлоу веб-интерфейс выдавал предупреждение: 
`В этом рабочем процессе используются пользовательские узлы, которые вы ещё не установили. Чтобы установить отсутствующие узлы, сначала выполните pip install -U --pre comfyui-manager...`

### Изначально предложенный код
В скрипте запуска не было предустановлено расширение `comfyui-manager`, а сервер запускался без флага `--enable-manager`.

### Причина ошибки
Специфические ноды переноса лица и стилизации требуют встроенного менеджера пакетов для разрешения зависимостей (скачивания отсутствующих скриптов) и явного разрешения от сервера на авто-менеджмент пакетов.

### Что пробовали и к чему привело
1. Пробовали клонировать только `ComfyUI_IPAdapter_plus` — привело к ошибкам отсутствия дополнительных вспомогательных нод в других частях графа.
2. Интегрировали автоматическую установку пакета `comfyui-manager` через pip и запуск сервера с флагом `--enable-manager`.

### Как решили (Финальный код)
Обновили ячейку запуска:
```python
# Установка менеджера
!pip install -U --pre comfyui-manager

# Запуск с поддержкой менеджера
!python main.py --listen 127.0.0.1 --port 8188 --enable-cors-header --enable-manager --dont-print-server
```
* **Результат:** ComfyUI-Manager успешно работает внутри веб-интерфейса, позволяя устанавливать любые отсутствующие ноды в один клик кнопкой "Install Missing Custom Nodes" прямо в браузере.
