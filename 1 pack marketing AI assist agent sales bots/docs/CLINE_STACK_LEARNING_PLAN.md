# Cline Stack Learning Plan

## Зачем этот файл

Это короткий практический план:
- какие skills для тебя самые полезные;
- что изучать в первую очередь;
- как применять это в реальных задачах, а не в теории.

Сделано именно под твой стек:
- AI-агенты;
- n8n;
- Telegram;
- автоматизации;
- код;
- VPS / деплой;
- быстрый запуск полезных штук.

---

## Топ-10 skills для твоих задач

### 1. implementation-research
**Почему в топе:**
Это один из самых полезных skills вообще.

Он нужен, когда не хочется изобретать велосипед, а хочется:
- найти готовую реализацию;
- взять mature pattern;
- посмотреть, как уже сделали нормальные люди.

**Практически применять так:**
- перед новой интеграцией;
- перед сложным workflow;
- перед новой архитектурой;
- когда нужна production-логика, а не фантазия.

**Примеры твоих задач:**
- WhatsApp automation patterns;
- n8n production workflow;
- Telegram bot patterns;
- RAG / AI agent system patterns.

---

### 2. local-code-search
**Почему в топе:**
Когда проект разрастается, руками искать становится больно.

Этот skill нужен, чтобы:
- быстро находить реализацию в локальном коде;
- понимать, где что уже сделано;
- не дублировать существующую логику.

**Практически применять так:**
- перед любыми правками в старом проекте;
- когда надо найти похожий workflow или интеграцию;
- когда хочешь понять структуру большого репо.

**Примеры твоих задач:**
- найти текущую логику WhatsApp;
- найти, где уже есть Telegram webhook;
- понять, как устроен конкретный n8n JSON или Python automation.

---

### 3. systematic-debugging
**Почему в топе:**
Очень полезен, когда что-то “почти работает”, но ломается неочевидно.

Он помогает:
- не тыкаться хаотично;
- искать root cause;
- фиксить причину, а не симптомы.

**Практически применять так:**
- webhook не срабатывает;
- n8n execution падает;
- бот отвечает странно;
- интеграция вроде есть, но данные не доходят.

**Примеры твоих задач:**
- Evolution API → n8n;
- Telegram → AI → ответ;
- broken automation chain;
- проблемы в AI-agent pipeline.

---

### 4. connect-automation
**Почему в топе:**
Это очень близко к твоим реальным задачам.

Нужен, когда строишь:
- автоматизации;
- связки между сервисами;
- webhook-процессы;
- agent-driven workflows.

**Практически применять так:**
- при проектировании новой автоматизации;
- когда связываешь несколько API;
- когда нужен понятный интеграционный workflow.

**Примеры твоих задач:**
- WhatsApp → n8n → AI → CRM;
- Telegram → voice → STT → summary;
- forms / webhook / DB / bot chains.

---

### 5. n8n-workflow-patterns
**Почему в топе:**
Тебе очень нужен не просто n8n, а **хороший n8n**.

Этот skill помогает:
- проектировать workflow правильно;
- выбирать паттерн до сборки;
- не городить хаос из 100 узлов без структуры.

**Практически применять так:**
- перед созданием нового n8n workflow;
- когда надо выбрать архитектуру;
- когда надо разделить orchestration и business logic.

---

### 6. n8n-executions-debug
**Почему в топе:**
Полезен, когда workflow уже есть, но он падает.

**Практически применять так:**
- execution failed;
- странные данные в узлах;
- webhook дошёл, но цепочка дальше сломалась;
- AI node ведёт себя нестабильно.

**Особенно полезен для тебя:**
Потому что у тебя много интеграций и длинных цепочек, где ошибка может быть не в первой ноде.

---

### 7. telegram
**Почему в топе:**
Telegram у тебя — один из главных рабочих каналов.

**Практически применять так:**
- при создании ботов;
- при уведомлениях;
- при сервисных командах;
- при быстрых интерфейсах управления процессами.

**Примеры твоих задач:**
- Telegram bot для алертов;
- personal assistant bot;
- уведомления о failed jobs;
- интерфейс для запуска AI-процессов.

---

### 8. hostinger-vps
**Почему в топе:**
Ты часто завязан на VPS и self-hosted сервисы.

**Практически применять так:**
- когда надо понять, где что крутится;
- когда надо деплоить;
- когда надо найти конфиг, compose, env, контейнер;
- когда надо чинить живую инфраструктуру.

**Примеры твоих задач:**
- n8n на VPS;
- wrappers;
- Docker stacks;
- Telegram / automation services.

---

### 9. browser-automation
**Почему в топе:**
Очень полезно, когда надо проверять UI и реальные пользовательские сценарии.

**Практически применять так:**
- проверить, как выглядит страница;
- воспроизвести баг;
- пройти форму;
- посмотреть консольные ошибки.

**Примеры твоих задач:**
- тест интерфейса;
- веб-админки;
- mini apps;
- быстрая проверка лендингов и демо.

---

### 10. deployment-guide
**Почему в топе:**
Когда нужно быстро понять, куда и как выкатывать проект.

**Практически применять так:**
- перед новым деплоем;
- когда неясно, что лучше: VPS / Railway / Render / Vercel;
- когда нужен нормальный deployment path без хаоса.

**Почему:**

## Как practically применять без теории

### Правило 1
Не учить все skills подряд.

Учить только так:
- возникла живая задача → использовать релевантный skill → смотреть, что он даёт.

---

### Правило 2
Не изучать skill «в вакууме».

Лучше так:
- есть проблема → применили skill → получили результат → зафиксировали, что он дал.

---

### Правило 3
Сразу привязывать к своим задачам.

Например:
- новый workflow → `n8n-workflow-patterns`
- поломанный webhook → `systematic-debugging` + `n8n-executions-debug`
- поиск готового решения → `implementation-research`
- большой старый проект → `local-code-search`
- VPS-проблема → `hostinger-vps`

## Быстрый шаблон: когда какой skill звать

→ `implementation-research`

### Если нужно быстро найти что-то в проекте
→ `local-code-search`

### Если баг сложный и непонятный
→ `systematic-debugging`

### Если строишь автоматизацию между сервисами
→ `connect-automation`

### Если создаёшь новый n8n workflow
→ `n8n-workflow-patterns`

### Если existing n8n workflow падает
→ `n8n-executions-debug`

### Если задача про Telegram
→ `telegram`

### Если задача про VPS / Docker / сервисы
→ `hostinger-vps`

### Если нужно пройти UI руками через агента
→ `browser-automation`

→ `deployment-guide`
