## [29.06.2026] Фикс подключения WhatsApp MCP к n8n (Ошибка: Cannot POST /sse)

**Проблема (Issue):**
При попытке подключить Evolution MCP сервер к n8n через SSE (Server-Sent Events) клиент n8n выдавал ошибку `Streamable HTTP error: Error POSTing to endpoint: Error Cannot POST /sse`. 
Это происходило потому, что клиент n8n почему-то отправлял POST-запросы с JSON-RPC payload прямо в корень подключения `/sse`, игнорируя правильный эндпоинт `/message`, который выдает стандартный `SSEServerTransport` из `@modelcontextprotocol/sdk`.

**Решение (Win):**
Был произведен прямой вход на VPS по SSH.
В файле `/opt/mcp-evolution-whatsapp-api/src/sse.ts` маршрутизатор Express был изменен, чтобы принимать POST-запросы как на `/message`, так и на `/sse`.
```typescript
// Старый код:
app.post("/message", async (req, res) => { ... })

// Новый код:
app.post(["/message", "/sse"], async (req, res) => { ... })
```

**Критический нюанс (Важный опыт):**
Изначально изменение файла и выполнение команды `docker restart mcp-evolution-whatsapp` не дало результата. 
**Причина:** Docker кэширует копирование файлов (`COPY . .`) на этапе сборки (`docker build`). Простой рестарт контейнера запускает старый кэшированный код.
**Правильный фикс:** Потребовалось полностью пересобрать образ (`docker build -t mcp-evolution-whatsapp -f Dockerfile.sse .`) и пересоздать контейнер (`docker run ...`). 

После полной пересборки интеграция успешно заработала. Баг n8n обойден на стороне сервера.
